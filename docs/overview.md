# Simulanka 总览

> 新文档组的入口：Simulanka 要做什么、分几部分、每部分什么功能、静态阶段的完成判据。
> 本篇只写现行结论。决策过程、历史依据、被否决的路在 `docs/design.md`（决策档案）。

## Simulanka 是什么

把一个科研项目的全部要素——问题、假设、实验、任务、运行、证据、结论，以及被研究的模型结构本身——放进一张可检查、可追溯的图。研究的过程就是这张图的演化，人始终能在画布上看见并裁决每一步。

三条全系统不变量：

1. **kernel 是图的唯一写者**——人、agent、工具都经它写图，写权矩阵约束谁能写什么，人的裁决最高（agent 覆盖不了）。
2. **测量归系统**——diff、验收、metrics、证据提取永远由确定性工具执行；agent 可触发，不可代笔结果。
3. **task / run 是第一等图实体**——一切执行都立项入图，不绕图。

## 静态与动态的分界

- **静态（先做）＝架子**：完备的图、图汇编语言（外部原文↔图的确定性转换）、agent 调用插座、友好的前端。
  验收判据：**人不借助任何 agent，就能亲手驱动一整轮研究循环，且全过程在前端可见、可点开、可追溯**；agent 插座验收＝免费模型跑一个玩具 task 全链前端可见，输出不作数（2026-07-09 定）。
- **动态（后做）＝血肉**：agent 的内容面——扮演分析者/操作员的 prompts、skills、角色工作流、输出质量调优、自动循环与刹车。静态架子过验收后才投入。

划界原则：**系统管调用、测量、写权三件事，不管 agent 输出什么**——输出要么被系统测量（执行类），要么以 proposed 态过写权闸等人裁（提议类）。静态阶段的驱动者是人；agent 是之后把人换下来的可替换驱动件。

## 静态部分的划分（三部分）

### 1. 图内核

图状态的唯一权威。

- 三原语 node / edge / port；内容寻址存储 + manifest + 事件日志（全历史可查）。
- 研究原子词表（question / hypothesis / experiment / task / run / evidence / claim / note）与语义边（addresses / tests / supports / contradicts / fulfills / produces …）。
- 唯一写路径（PatchIntent → apply_patch）+ 写权矩阵；`graph` 查询/变更 CLI；`doctor` 图健康自检。

### 2. 图汇编语言（外部原文 ↔ 图的确定性转换）

统一抽象：**文档、模型、执行现场都是外部原文，图是它们的可检查投影**。每一种转换都是确定性工具——同样的原文必得同样的图，工具可信 ⇒ 结果可信。人和任何模型只需读写原文，不直接操作图。

**文档 ↔ 图**：

- **plan 块**（文→图）：分析者的计划文件 = 自由 prose + 恰好一个结构块，`plan ingest` 原子落图。（S9 定案后由轮次手稿文件夹取代、结构块退役——见 assembly.md「手稿层改造」。）
- **brief 块**（图→文）：`brief export` 导简报，与 plan 块镜像对偶——简报给出的图 id 就是下轮计划可直接引用的 id。
- **ops 块**（受限写入）：核对/讨论会话中对图的最小写入协议。

**模型 ↔ 图**：

- **manifest + import**（模型→图）：baseline 的声明式成图（`import torch/baseline`），trace 数据流边确定可信，structure-only 兜底，manifest 杜绝漏组件。
- **export**（图→可视化格式）：Model Explorer 等第三方格式导出。

**执行现场 → 图**：

- **run 括号**（`run begin/end`）：执行事实的如实投影——begin 记基线，end 算 diff、跑验收、记时长与状态；中间干活的是人还是 agent，系统不管。
- **evidence 提取**（`evidence extract`）：metrics 文件 → 证据节点（`source=machine`），只记测量、不做语义判断。

**agent 调用（插座）**：

- `run agent`：run 括号的自动化形态——起一个 agent CLI（argv 模板包装，不接管其 skills/MCP）在括号中间干活，收口同 run end。
- 讨论 harness：锚定对话里起 agent（session 续聊），其写图只能走 ops 块过写权闸。
- `propose`：起 agent 提议数据流边，产出一律 proposed 态等人裁。
- 调用本身不产图内容——agent 产出进图只走上面两条路：测量投影，或写权闸受限写入。调什么 prompt、装什么 skill、输出好不好，属动态。

表达力目标：图能表达的研究叙事，原文侧最终都能表达；缺口由真实使用首撞驱动补齐，不预补。

### 3. 前端

人的唯一检查面与裁决面——把关人不读代码，读画布。

- 统一 node-edge-port 渲染器、双击下钻、跨层边界端口投影、属性侧栏、SSE 实时刷新。
- 人画连线（结构图缺的数据流边由人补画、人终裁）、锚定核对（就地裁决 + 导航清单；核对/讨论面板 2026-07-10 定退役）、锚定式讨论（对话必锚定画布选择集，批次＝多选锚；消息不进图，留在会话文件）。
- 研究轮次视图：按轮下钻（每计划一目录）、节点一键深链文档出处。
- 可信度染色 + 血缘链展示（摆链条给人看，不折叠成分数替人判断）。

## 不在静态验收范围

- **动态血肉（agent 内容面）**：扮演分析者/操作员的 prompts 与工作流、skills 实跑验证（Codex 四篇已入库备用）、边提议/核对的质量迭代、命门 C、自动循环与刹车细节、快检工具、MCP 适配层。
- **最终美术风格**（原神童话风）：不作为静态验收条件，随前端波次择机推进。
